## What to build

An owner describes their business and publishes a readable, testable setup without writing code or being forced into a qualification funnel.

Implement one complete owned Rails/Vue path across storage, permissions, API, jobs/provider and UI. Follow the approved 12 September product agreement and ADR 0016. Preserve MIT, tenant isolation, consent, canonical delivery and current evidence.

## Acceptance criteria

- [ ] One guided Business setup covers About, Products/services, Prices/promotions, optional fit requirements and next step. Accept prose/documents and show source-linked proposed facts/rules/unknowns for review.
- [ ] Owner approves a plain-language preview and publishes a versioned configuration; no unapproved extraction executes. Preserve draft edits, errors, conflict resolution, permissions and source history.
- [ ] Explicitly choose not-configured/disabled/enabled qualification and answer-only, purchase/enquiry link or eligible booking next steps. Missing configuration blocks only dependent actions, never restores global default questions.
- [ ] Extracted prices use R20 authoritative entry; a single edit location prevents contradictory duplication. Link existing UI paths rather than introducing competing knowledge/rules editors.
- [ ] Test this setup uses the same authorised runtime and source revision as inbound conversations with no live-send side effects. Explain missing rules/prices/actions in simple language.
- [ ] Demonstrate Online Profits as editable sample data with unconfirmed prices withheld, a product business with no qualification/call, and another service with different fit rules. Show English/Swahili, corrections, human help, phone and desktop, stale response isolation and publish conflicts.

## Delivery

One focused task/branch from coordinator-approved integrated blockers. Test behavior first, run focused checks/build, review the diff and use the in-app browser. Record immutable evidence and limitations. Only the coordinator integrates, pushes and closes. No deployment, customer sends or uncapped provider spending is authorised by ticket readiness.
