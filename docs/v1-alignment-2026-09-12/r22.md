## What to build

The Platform Operator can select a cost-effective model using comparable saved evidence instead of provider marketing.

Implement one complete owned Rails/Vue path across storage, permissions, API, jobs/provider and UI. Follow the approved 12 September product agreement and ADR 0016. Preserve MIT, tenant isolation, consent, canonical delivery and current evidence.

## Acceptance criteria

- [ ] Create a repeatable comparison using the same authorised synthetic/de-identified English and Swahili scenarios, source/config versions, model identifiers and generation settings; preserve raw outcomes and reviewer rubric.
- [ ] Cover relevant questions, unsupported questions, business-specific and disabled qualification, corrections/negation, pricing, prompt injection, free-consulting boundaries, handoff, consent and human control.
- [ ] Report per-scenario accuracy, critical failures, qualification errors, latency and actual full pipeline cost including internal calls/retries/cache where supplied. Unknown cost is explicitly missing, not zero; avoid aggregate accuracy that conceals silence.
- [ ] Compare several candidate models chosen from current supported providers. No live Lead sends. Prepare dry-run fixtures first; execute paid comparisons only under an explicit total spend cap and approved provider connection.
- [ ] Present one recommended service standard only after critical cases pass and cost/quality evidence supports it. Publish a reviewed model choice through the platform configuration path and invalidate stale launch evidence.
- [ ] Test runner and report with deterministic fake responses, then record separately bounded provider-backed results. Package prices and allowances remain hypotheses until supported by measured costs.
